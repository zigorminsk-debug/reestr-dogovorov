# Реестр договоров

Сетевое Windows-приложение для регистрации договоров клиентов и подрядчиков с HTML-интерфейсом. Серверная часть, общая SQLite-база, совместное редактирование, импорт исходного Excel-реестра, отчёты, экспорт и печать.

Поля соответствуют файлу **`Реестр договоров1.xlsx`** из репозитория. Исходный файл сохранён без изменений.

## Возможности

- регистрация, редактирование и удаление договоров через отдельное модальное окно;
- все 17 колонок образца: контрагент, страна, договор, заявка, счёт, оплата, срок, АВР, НДС, валюта, клиент, примечания и платёжное поручение;
- одновременная работа пользователей с одной серверной базой;
- оптимистичная блокировка по версии записи: при одновременном редактировании программа не даёт затереть чужие изменения;
- история создания, импорта, изменения и удаления с именем пользователя;
- дашборд с ближайшими оплатами и просрочками;
- отчёты по контрагентам, срокам оплаты и просроченным оплатам;
- отдельный учёт непогашенной просрочки и оплаты позже срока;
- итоги в разрезе валют, без сложения разных валют в одну сумму;
- экспорт отчётов в настоящие **Excel `.xls`**, **Word `.docx`** и **PDF** с встроенным кириллическим шрифтом;
- печать сформированного отчёта из HTML-интерфейса;
- предпросмотр импорта `.xlsx` / `.xls`, построчная проверка и защита от повторной загрузки того же файла;
- скачивание шаблона импорта и резервной копии SQLite;
- автоматические резервные копии по ежедневному расписанию в локальный или сетевой каталог;
- настраиваемое количество хранимых копий и статус последнего запуска;
- восстановление из списка копий или загруженного `.db`-файла без остановки сервера;
- проверка целостности и структуры файла, автоматическая страховочная копия перед восстановлением;
- автономная работа в локальной сети без CDN и внешних веб-сервисов;
- отдельный вход администратора для всех операций с копиями: настройки, список, создание, скачивание и восстановление; обычные пользователи по-прежнему работают по имени без пароля.

## Установка на сервер

Готовый `ReestrDogovorov-Setup-1.2.0.exe` создаётся в GitHub Actions (см. ниже).

1. Скачайте установщик из артефакта успешной сборки **Windows Setup**.
2. Запустите его на Windows Server или выделенном Windows-компьютере от имени администратора.
3. При первой установке (и при обновлении версии без администратора) мастер попросит логин, пароль и подтверждение пароля администратора резервных копий. Пароль должен содержать от 8 до 256 символов. Сохраните эти учётные данные у ответственного сотрудника: это отдельный вход, не имя обычного пользователя. При последующих обновлениях существующая учётная запись сохраняется, а страница её создания пропускается.
4. Установщик:
   - размещает программу в `Program Files\ReestrDogovorov`;
   - создаёт задачу автозапуска `ReestrDogovorov Server` под `SYSTEM`;
   - запускает HTTP-сервер на `0.0.0.0:8080`;
   - разрешает входящий TCP-порт 8080 для доменного и частного сетевых профилей;
   - создаёт серверный ярлык и файл `Клиентский ярлык.url`;
   - сохраняет исходный образец в папке `Образцы` внутри каталога установки.
5. На сервере ярлык открывает приложение в отдельном окне Edge/Chrome (при наличии), иначе в браузере по умолчанию.

Пароль не передаётся в командной строке. Установщик записывает его только во временный защищённый файл с доступом для `SYSTEM` и администраторов Windows, после инициализации файл удаляется. В `auth.json` сохраняются логин и хэш PBKDF2-SHA256, но не открытый пароль.

### Подключение рабочих мест

1. Откройте каталог установки на сервере.
2. Скопируйте **`Клиентский ярлык.url`** на рабочий стол пользователя.
3. Запуск ярлыка открывает общий HTML-интерфейс по адресу `http://ИМЯ-СЕРВЕРА:8080/`.
4. При первом использовании пользователь указывает имя для истории изменений.

Если DNS-имя сервера недоступно рабочим местам, откройте `.url` в Блокноте и замените имя на IP-адрес, например:

```ini
[InternetShortcut]
URL=http://192.168.1.20:8080/
```

Устанавливать Python или саму программу на рабочие места не нужно. Между компьютерами должен быть доступен TCP-порт сервера.

## Где хранятся данные

База расположена **отдельно от исполняемых файлов**:

```text
%ProgramData%\ReestrDogovorov\
├── data\reestr.db       # общая база
├── server.json          # хост и порт
├── auth.json            # логин и хэш пароля администратора, отдельно от базы
├── backup_settings.json # расписание, каталог и статус копирования
├── backups\             # ручные копии и backups\safety — страховочные
├── exports\
└── logs\server.log
```

Обновление поверх существующей установки заменяет программу, но **не удаляет и не перезаписывает этот каталог**. Учётная запись администратора хранится вне `reestr.db`, поэтому сохраняется и при обновлении, и при восстановлении базы из старой копии. Дополнительная защита от потери изменений: SQLite WAL, транзакции `BEGIN IMMEDIATE`, тайм-аут занятой базы и версии записей.

Перед обновлением и массовым импортом рекомендуется нажать **«Скачать резервную копию»** в левом меню.

Для нестандартного порта измените `server.json`, затем перезапустите задачу `ReestrDogovorov Server` и обновите сетевой ярлык/правило брандмауэра. При следующей установке `register-server.ps1` читает сохранённый порт.

## Резервные копии и восстановление

В правом верхнем углу нажмите **«Администратор»** и войдите с учётными данными, созданными при установке. После входа появится раздел **«Копии и восстановление»**; во встроенной инструкции описаны все операции. Сессия действует 12 часов и хранится в `HttpOnly` cookie. Кнопка **«Выйти»** находится в окне администратора.

Обычные пользователи по-прежнему указывают только своё имя для истории и работают с договорами, импортом и отчётами без пароля. Раздел копий для них скрыт. Подмена заголовка `X-Operator` прав администратора не даёт: каждый backup/restore/settings/download API проверяет серверную административную сессию.

### Расписание

1. Включите ежедневное копирование.
2. Укажите время на сервере, абсолютный каталог и число хранимых копий (1–100).
3. Нажмите **«Сохранить расписание»**.

Поддерживаются локальные пути вроде `D:\Backups\Reestr` и UNC-пути вроде `\\NAS\Share\Reestr`. Путь задаётся **на сервере**. Серверная часть работает под `SYSTEM`, поэтому у этой учётной записи должны быть права записи в сетевой папке. Если сервер был выключен в назначенное время, пропущенная копия создаётся после запуска в тот же день. Настройки и статус находятся в `backup_settings.json` отдельно от базы и не сбрасываются при восстановлении.

### Простое восстановление

- Из имеющейся копии: нажмите **«Восстановить»** в её строке.
- Из скачанного файла: выберите `.db` в блоке **«Восстановить базу с этого компьютера»**.

Затем введите `ВОССТАНОВИТЬ` и подтвердите операцию. Программа:

1. проверяет SQLite-файл, целостность и наличие таблиц реестра;
2. приостанавливает новые запросы пользователей и ждёт завершения текущих;
3. создаёт страховочную копию текущей базы в `backups\safety`;
4. заменяет базу и проверяет её повторно;
5. возвращает прежний файл при ошибке и возобновляет работу без ручного перезапуска.

После успешного восстановления показывается количество записей и расположение страховочной копии. Администратор и имя файла записываются в `logs\server.log`.

### Восстановление доступа администратора

При запуске **из исходников** на сервере выполните `python run.py --reset-admin`: логин, пароль и подтверждение будут запрошены интерактивно. Команда `--init-admin` создаёт учётную запись только если её ещё нет.

В **установленной версии** администратор Windows может переименовать `%ProgramData%\ReestrDogovorov\auth.json`, например в `auth.previous.json`, и повторно запустить Setup 1.2.0. Мастер предложит создать нового администратора, не затрагивая договоры, настройки и резервные копии. После успешного входа старый файл можно удалить. Смена учётной записи немедленно аннулирует прежние административные сессии.

## Импорт исходного реестра

1. Откройте **Импорт Excel**.
2. Выберите `Реестр договоров1.xlsx`.
3. Проверьте предпросмотр и нажмите **«Импортировать»**.

Составные значения автоматически разбираются:

- `К88 от 01.03.2026` → номер `К88`, дата `2026-03-01`;
- `1 от 04.03.2026` → номер и дата заявки;
- `без заявки` сохраняется как текст заявки;
- дата в колонке «СРОКИ ОПЛАТЫ» становится плановой датой;
- текст вроде `30 дней` сохраняется как условия оплаты.

Строки с ошибками показываются отдельно и не импортируются. Корректные строки записываются одной транзакцией. Точно такой же файл нельзя импортировать повторно, что предотвращает дубликаты.

## Логика просрочки

- **Просрочено**: счёт не оплачен, а срок оплаты раньше текущей даты. Дни просрочки считаются до сегодняшнего дня.
- **Оплачен с просрочкой**: фактическая дата оплаты позже срока. Дни просрочки считаются между сроком и оплатой.
- **Оплатить в ближайшие 7 дней**: неоплаченный счёт со сроком от сегодня до +7 дней.

## Запуск из исходников

Требуется Python 3.11+:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt
python run.py --init-admin  # один раз; логин и пароль будут запрошены интерактивно
python run.py --serve --host 0.0.0.0 --port 8080
```

Откройте `http://localhost:8080/`. Для локальной разработки база создаётся в `%ProgramData%\ReestrDogovorov` на Windows или `~/.reestr-dogovorov` на Linux/macOS. Каталог можно переопределить переменной `REESTR_DATA_DIR`.

Переменные `REESTR_HOST`, `REESTR_PORT` и `REESTR_URL` переопределяют параметры запуска и ярлыка.

### Тесты

```bash
pytest
node --check reestr/static/app.js  # если установлен Node.js
```

Тесты проверяют CRUD, конфликт версий, имена пользователей, импорт именно репозиторного образца, отчёты, просрочки, настоящие форматы XLS/DOCX/PDF, целостность резервной копии, запрет анонимного доступа ко всем backup API, хэширование пароля, вход/выход, ограничение попыток и срок административной сессии.

## Сборка в GitHub Actions

Workflow: **`.github/workflows/build-windows.yml`**.

При push, pull request или ручном запуске **Windows Setup** на `windows-latest` выполняются:

1. установка зависимостей;
2. автоматические тесты;
3. PyInstaller-сборка серверной части и HTML-ресурсов;
4. smoke-тест упакованного EXE: инициализация администратора через защищённый файл, запрет анонимной копии, вход по cookie, создание/восстановление копии, HTML и PDF;
5. компиляция `Setup.exe` через Inno Setup;
6. публикация артефакта `ReestrDogovorov-Windows-Setup` и SHA-256.

Для локальной Windows-сборки:

```powershell
pip install -r requirements-dev.txt
python -m PyInstaller --noconfirm --clean packaging/ReestrDogovorov.spec
# После установки Inno Setup 6:
& "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" packaging/installer.iss
```

## Безопасность

Приложение рассчитано на доверенную локальную сеть. Имя обычного пользователя служит для журнала операций и не заменяет аутентификацию. Операции с резервными копиями защищены отдельным входом администратора; пароль хранится только как PBKDF2-SHA256 с 600 000 итераций и случайной солью. После пяти неверных попыток вход с того же сетевого адреса временно блокируется на пять минут.

Сервер работает по HTTP, поэтому не публикуйте порт 8080 напрямую в интернет: для внешнего доступа нужны HTTPS и ограничение доступа на уровне инфраструктуры. Файл `auth.json` и временный bootstrap-файл установщика защищаются ACL только для `SYSTEM` и администраторов Windows.
