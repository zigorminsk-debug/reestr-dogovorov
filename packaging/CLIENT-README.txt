ПОДКЛЮЧЕНИЕ ПОЛЬЗОВАТЕЛЕЙ К РЕЕСТРУ ДОГОВОРОВ

1. Установите программу на сервер под учётной записью администратора Windows.
2. При первой установке мастер попросит создать логин и пароль администратора
   резервных копий. Сохраните их у ответственного сотрудника. При обновлении
   существующий администратор сохраняется, повторно создавать его не нужно.
3. После установки в папке программы появится файл «Клиентский ярлык.url».
4. Скопируйте этот файл на рабочий стол каждого пользователя. Устанавливать
   программу и Python на рабочие места не требуется.
5. При двойном щелчке по ярлыку откроется окно браузера с общим реестром.
6. В правом верхнем углу пользователь один раз указывает своё имя. Оно будет
   записываться в историю создания и изменения договоров. Пароль обычному
   пользователю не нужен.

Сетевой адрес ярлыка имеет вид http://ИМЯ-СЕРВЕРА:8080/.
Если имя сервера не находится в вашей сети, замените его в файле .url на
IP-адрес сервера, например http://192.168.1.20:8080/.

На сервере входящий TCP-порт 8080 разрешается для профилей «Доменный» и
«Частный». Между рабочими местами и сервером этот порт должен быть доступен.

ОБЩАЯ БАЗА И ОБНОВЛЕНИЯ
База находится отдельно от программы:
%ProgramData%\ReestrDogovorov\data\reestr.db

Учётная запись администратора находится отдельно от базы:
%ProgramData%\ReestrDogovorov\auth.json
В ней сохраняются логин и хэш пароля, но не открытый пароль. Учётная запись
сохраняется при обновлении программы и восстановлении базы из копии.

При обновлении установщик заменяет только файлы программы. Каталог
%ProgramData%\ReestrDogovorov не удаляется и не перезаписывается.

РЕЗЕРВНЫЕ КОПИИ И ВОССТАНОВЛЕНИЕ — ТОЛЬКО ДЛЯ АДМИНИСТРАТОРА
Нажмите «Администратор» в правом верхнем углу и введите логин и пароль,
созданные при установке. После входа откройте «Копии и восстановление».
В разделе находится подробная встроенная инструкция. Обычное имя пользователя
не даёт доступа к копиям, даже если ввести имя admin.

Для автоматического копирования включите расписание, укажите время, каталог на
сервере и количество хранимых копий. Можно указать локальный путь, например
D:\Backups\Reestr, или сетевой \\NAS\Share\Reestr. У учётной записи SYSTEM
должны быть права записи в выбранный каталог.

Для восстановления нажмите «Восстановить» в строке нужной копии или выберите
ранее скачанный .db-файл. Введите слово ВОССТАНОВИТЬ и подтвердите операцию.
Останавливать сервер вручную не требуется. Программа проверит файл, временно
приостановит запросы пользователей и сначала создаст страховочную копию текущей
базы в %ProgramData%\ReestrDogovorov\backups\safety. После восстановления
появятся данные на дату выбранной копии.

После завершения работы с копиями нажмите «Администратор» и затем «Выйти».
Административная сессия также автоматически заканчивается через 12 часов.
